<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Controller to independent guard | The controller cannot be trusted to remain connected or to extend its own deadline. |
| Controller to provider and desktop website | Provider responses and UI targets can be wrong, stale, or not owned by this run. |
| Credential file to controller | Secret material must remain confidential and may only be read from a tightly controlled location. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-01-06 | Elevation | guard.py | mitigate | Require independent-host attestation, immutable deadline, heartbeat-loss trigger, and exact ID/label/nonce ownership check. |
| T-01-07 | Spoofing | reporting.py | mitigate | Exact-instance UI preflight and ownership validation before report capture or submit. |
| T-01-08 | Repudiation | controller.py | mitigate | Journal all side-effect intents, receipt/timeout outcomes, heartbeats, and absence reads. |
| T-01-09 | Information disclosure | controller.py | mitigate | `0600` secret source validation; redact/forbid credentials in repo, artifacts, argv, env, and logs. |
| T-01-10 | Denial of service | controller.py | mitigate | Bounded report window and independent guard deadline preserve teardown authority when reporting fails. |
| T-01-SC | Tampering | Python dependency setup | accept | The plan uses existing pytest tooling and no package installation. |
</threat_model>
